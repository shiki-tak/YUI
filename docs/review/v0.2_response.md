### Warning 2：評価器の `expect_no_new_question` は「相手の質問が残っているため対象外」に到達できず、実装が意図的に通した返答を失敗と判定する

**妥当。修正した。**

#### 確認したこと

レビューの再現手順（シナリオ4を FakeLLM で2回とも質問付きの返答にして流す）をそのまま再現しました。

```
実装（conversation.py）の判定：closing_unresolved_due_to_open_question = True（対象外が正しい）
評価器がターン後に見る会話状態での判定：has_unanswered_question_to_yui = False（未応答が無いように見える）
結果：「新しい質問が無い」チェックが False で失敗
```

原因はレビューの指摘どおりでした。実装は**生成前**の会話状態（`responded_message_id` がまだ空）で「相手の質問が未応答か」を判定しますが、評価器は**ターン完了後**に同じ関数へ、その返答自身が `responded_message_id` を埋めた後の会話状態を渡していたため、同じターンで相手が質問したケースでは「対象外」の分岐に決して到達しませんでした。

#### 直し方

評価器が独自に「未応答の質問があるか」を計算するのをやめ、実装がそのターンで実際に下した判定（`RunRecord.options["checks"]["closing_unresolved_due_to_open_question"]`）をそのまま使うようにしました。`_check_turn` に `run_checks: dict[str, object]` を引数として追加し（[runner.py:266-273](../../backend/app/evaluation/runner.py#L266-L273)）、`expect_no_new_question` の判定はこの値を見るように変更しています（[runner.py:360-368](../../backend/app/evaluation/runner.py#L360-L368)）。呼び出し元では `result.run.options.get("checks", {})` を渡します。実装と評価器が同じ関数ではなく同じ結果を参照する形にしたので、今後どちらかの判定条件だけを変えて食い違う心配がありません。

あわせて、レビューが「付随」として指摘した `has_unanswered_question_to_yui` が `status` を見ていない点（実装側は `get_open_states` で `open` 済みの一覧しか渡さないため実害は無いが、将来 `withdrawn`／`expired` の行を渡す呼び出し元が増えると壊れる）も、`status == open` の条件を明示的に足して塞ぎました（[conversation_state.py:574-591](../../backend/app/agent/conversation_state.py#L574-L591)）。

#### 確認

レビューの再現手順をそのままスクリプトにして、修正後は「対象外（人手判定と併用）」として通ることを確認しました。`tests/test_evaluation.py` の既存の `_check_turn` 呼び出し7箇所は、新しい引数（`run_checks`）を空辞書で渡す形に更新しています。

### 対応で確認した既存機能への影響

実測（3本×3回、`logs/evals/20260913T141036-2026-09-07.1`）を根拠に、**各シナリオ3回中2回以上（過半数）で「答え損ねた状態で自分の話題へ移らない」を満たす**ことを閾値として設計書に明記しました（[ai_vtuber_architecture.md:524](../design/ai_vtuber_architecture.md#L524)）。この閾値で判定すると、答え損ね系3本のうち2本（2/3ずつ）は閾値を満たし、1本（0/3）は満たしません。記録側の(3)行を「3本中2本が閾値達成、1本は未達」という具体的な内訳に書き直しました（[result/v0.2.md:135](../result/v0.2.md#L135)）——判定自体は引き続き△ですが、根拠が「なんとなく半分」から「決めた閾値に対して2/3本が届いている」に変わっています。

あわせて、同じ節の「対象外と既知の制限」にあった「解釈の LLM 呼び出しが増えるため待ち時間が伸びうる（測ってから常時有効にするか決める）」という未来形の記述も、PR5 で測定・判断済みである実態に合わせて「測った結果、既定は無効のまま」に直しました（[ai_vtuber_architecture.md:523](../design/ai_vtuber_architecture.md#L523)）。これは Nit として指摘されていた点です。
