# フェーズ3 Pre review への対応

対象：[docs/review/codex/phase3_review.md](../codex/phase3_review.md)（ISSUE-014：固定人格の版管理）

対応日：2026-09-07

**結論：指摘2件はいずれも実際の不具合でした。2件とも修正し、再発を検知するテストを追加しました。**

どちらも「コード確認のみ」として報告されたものですが、こちらで再現を確認してから直しています。修正前に追加したテストが実際に失敗することも確認しました。

## 指摘1：人格の読込に失敗すると、振り返り開始済みの状態だけが残る

**妥当。修正した。**

### 確認したこと

`POST /conversations/{id}/end` は、振り返りの開始権を UPDATE で確定して `commit()` した後、`try:` の中で `extract_candidates(..., character_name=load_persona().name)` を呼んでいました。引数の評価は `try:` の内側ですが、`except (LLMError, ReflectionParseError)` は `PersonaError` を捕まえません。そのため `_release_reflection()` が実行されず、開始権を握ったまま 500 で終わります。

指摘のとおり、`reflection_stale_seconds`（既定180秒）を過ぎるまで再試行が409になります。人格ファイルを直しても待たされます。

これは今回の変更で新しく入った経路です。以前の `BASE_PERSONA.name` は定数で、失敗しませんでした。ファイルを読む処理を、開始権を取った後の区間に置いてしまったのが原因です。

### 直し方

**開始権を取る前に人格を解決する**ようにしました（[conversations.py:130](../../../backend/app/api/conversations.py#L130)）。失敗しても、DBには何も残りません。`try` の中に人格の読み込みを残して `except` を増やす方法もありますが、開始権を取った後に失敗しうる処理をこれ以上増やさない形を選びました。

あわせて、指摘にあった「起動時検証が無い」点も直しています。

- `app.main` に lifespan を足し、**起動時に既定の人格を読んで確かめる**ようにしました。設定の誤りが、最初のリクエストではなく起動で分かります。
- `PersonaError` の例外ハンドラを足し、起動後に版のファイルが壊れた場合などを **503 と原因の分かる本文**で返すようにしました（500 で潰さない）。
- `PersonaError` の説明文が「起動時に落とす」と実際の挙動から外れていたので、実装に合わせて直しました。

### 確認

- `tests/test_persona_versions.py::test_reflection_claim_is_released_when_the_persona_cannot_be_read` を追加。人格を読めない状態で終了APIを呼び、**503が返ること**と、**人格を直した直後にやり直せる（200）こと**を見ます。修正前は 500 のあと 409 になり、このテストは失敗します。
- 起動時検証は実際に動かして確認しました。人格ディレクトリを空にすると lifespan が `PersonaError` で停止し、正常時は起動します。

## 指摘2：personas 内のシンボリックリンクからディレクトリ外を読める

**妥当。修正した。再現も確認した。**

### 確認したこと

再現しました。`personas/sneaky.toml` を外部ファイルへのシンボリックリンクにすると、

```
一覧に出るか: ['sneaky']
読めたか: 外部のファイル ['personas の外から読み込まれた。']
```

版名の文字種検証（`_VERSION_PATTERN`）は名前しか見ておらず、`Path.is_file()` と `read_text()` はリンク先を辿ります。不変条件4「personas ディレクトリの外を読めない」を満たしていませんでした。

指摘が「遠隔から任意ファイルを読めると断定するものではない」と限定しているとおり、リンクを作る経路はAPIにありません。ローカルにリンクが存在する場合の不備です。

### 直し方

`_persona_file()` を追加し、**解決した先が人格ディレクトリの直下にある場合だけ**パスを返すようにしました（[persona.py](../../../backend/app/persona.py)）。

- 読み込み（`load_persona`）と一覧（`available_versions`）で同じ判定を使います。一覧に出るのに読めない版があると、会話ごとの指定が通ったり通らなかったりするためです。
- ディレクトリ自体を別の場所へ向ける設定（`YUI_PERSONA_DIR`）は、運用者の明示的な指定なので許します。制限するのは、そのディレクトリの中から外へ出ることです。

修正後は一覧に出ず、直接指定すると `PersonaError` になります。

### 確認

- `tests/test_persona_versions.py::test_symlink_out_of_the_persona_directory_is_not_loaded` を追加。同じディレクトリ内の実ファイルは読めることも一緒に見ます。修正前は一覧に `sneaky` が出て失敗します。
- 実際のファイルシステムでも、修正後にリンク先を読まないことを確認しました。

## 「対象外・未確認」への判断

指摘として数えられていない項目です。今回は直していません。理由を残します。

| 項目 | 判断 |
| --- | --- |
| キャッシュのキーに設定が入らない（`load_persona()` と `load_persona(None)` が別キーになる） | 直さない。どちらも同じ定義を返すため、動作の差はありません。稼働中に設定を読み直す仕様は持たせていません。**TOML を編集したら再起動が要る**点は、版を比較する作業で効くため、ISSUE-014 の記録に明記しました |
| `frozen=True` でもリストの中身は変更できる | 直さない。キャッシュを共有するため、変更されれば以後の全リクエストが汚れます。ただし現在の呼び出し元に変更する処理は無く、指摘も未確認としています。タプルへ変えると `PersonaOut` とテストにも波及するため、実害が出るか、3Aで人格を触る処理が増える時点で判断します |
| downgrade で版の情報が失われる | 直さない。列を落とす以上、避けられません。移行の記録に「既存行は NULL のまま」と書いてあり、戻す運用は想定していません |
| 移行の往復（既存データを含む upgrade／downgrade）が未実行 | 未確認のままにします。追加した列は nullable で、既存行に触れません |
| テストの任意順序・並列実行が未確認 | 未確認のままにします。現在 pytest に並列実行の設定はありません |
| 実 Ollama・VOICEVOX・実ブラウザ | 未確認です。今回の変更はすべてモック越しの確認です |
