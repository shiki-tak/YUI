## 指摘1：`active_goals` が現在時刻を UTC へそろえず、実行日時を誤判定する

**妥当。修正した。再現も確認した。**

### 確認したこと

`due_at` は `normalize_due_at` で保存前に UTC へ直していましたが、**比較に使う
`now` はそのまま SQL へ渡していました**。SQLite は timezone を落として比較する
ため、日本時間で渡された `now` は、その壁時計の値が UTC として扱われます。

指摘の表のとおり、同じ瞬間でも表記によって結果が変わります。基準日時 9/13 15:30
UTC の目標に対し、9/13 15:00 UTC（まだ実行してはいけない）を同じ瞬間の
9/14 00:00 JST として渡すと、実行してよいと判定されました。

**保存側だけそろえても足りない**、というのが今回の穴です。記憶の `occurred_at`
で踏んだずれ（日本時間 00:30 の発言が前日扱いになる）と同じ形が、比較側に
残っていました。

### 直し方

`as_utc()` を切り出し、保存（`normalize_due_at`）と比較（`active_goals`）の
両方で同じ関数を通すようにしました（[goal.py](../../../backend/app/agent/goal.py)）。

- timezone を持つ値は UTC へ直す。
- timezone を持たない値は UTC として解釈する。保存が UTC なので、DB から読み
  戻した値をそのまま渡しても同じ基準になります（`config.to_local` と同じ約束）。

`now` を受け取る関数は今後も増えます（評価に `advance_time` を足す PR3、期限
切れを判定する PR9）。経路ごとに直すのではなく、**時刻を受け取る側が1か所で
そろえる**形にしました。

### 確認

`tests/test_goal.py::test_the_same_moment_is_judged_the_same_in_any_timezone` を
追加しました。同じ瞬間を UTC・UTC+9・UTC−7 の3通りで渡し、基準日時の前後で
判定が一致することを見ます。あわせて次の2つも入れています。

- 境界：`now == due_at` は「以降」に含める。
- timezone を持たない `now` を UTC として扱う。

`now` の正規化を戻すと、このテストが失敗することを確認しました（修正前の状態を
再現して1件失敗、戻して11件成功）。

## 指摘3［中］：時間を進めた後の発言が実時計の日付で保存される

**妥当。修正した。再現も確認した。**

### 確認したこと

30日進めて「昨日、映画を見たよ」と発言し、振り返りへ渡るプロンプトを見ました。

```
[#1／2026-09-08] 開発者: 昨日、映画を見たよ        ← 実時計
振り返りを行っている日: 2026-10-08                  ← 進めた時計
```

振り返りは「相対的な日付は、その言い方が出てきた発言の日付から数える」設計
なので、**1か月ずれた入力を渡していました**。

### 直し方

出来事の時刻と、監査の記録を分けました。

- 発言（`messages.created_at`）は、会話に渡した現在時刻と同じ基準で保存する。
- 評価で採用した記憶（`memories.created_at`）も同じ。検索の減衰が、まだ作られて
  いない記憶を新しいものとして扱わないため。
- 再生の記録（`delivery_started_at` / `delivery_finished_at`）は実時計のまま。
  いつ鳴らしたかは監査の記録で、会話の中の時間の進み方とは別のもの。

通常の呼び出しは `now` を渡さないので、これまでと同じ実時計で動きます。

### 確認

`test_the_advanced_clock_reaches_the_saved_message` で、会話ログの発言日と
振り返りが「今日」とする日が揃うことを見ます。

## PR4：目標の API と画面 — 第1回レビューへの対応（2026-09-08）

**結論：指摘4件すべて妥当でした。4件とも直し、再発を検知するテストを追加しました。**

3件は「終わったはずの目標や、無効な根拠を持つ目標が、印の付かない実行候補に
なる」という同じ形でした。状態の遷移を表にして1か所で検査するようにしています。

## 状態の遷移を決めた

指摘2・3への対応の前提として、API が許す遷移を確定しました
（[goals.py](../../../backend/app/api/goals.py) の `_ALLOWED_TRANSITIONS`）。

| いまの状態 | 変えられる先 | 理由 |
| --- | --- | --- |
| pending | なし（decide のみ） | 採用は根拠の補完と `accepted` の履歴を伴う |
| active | done / withdrawn / cancelled / expired | 終わり方は区別して残す |
| withdrawn | active / cancelled / expired | 一時的に外した状態なので戻せる |
| done / rejected / cancelled / expired | なし | 終わり。前提が戻ったのなら作り直す |

## 指摘1［中］：削除済みの記憶を根拠に新規作成した目標を採用できる

**妥当。修正した。**

`_check_scope_against_basis` は記憶の存在と参照範囲しか見ておらず、
`status` を見ていませんでした。**訂正の波及は「後から変わったもの」を拾う
仕組みなので、作る前に無効だった根拠は拾えません。**

2か所を直しました。

- 作成（POST）：無効な記憶を根拠に指定したら 400 で拒否する。訂正後の記憶を
  根拠にするよう促します。
- 採用（decide accept）：候補を置いてから採用するまでの間に根拠が消えることが
  あるため、`_dead_basis` を見て、消えていれば `needs_review` を立てる。
  拒否はしません。目標を捨てるかは開発者が決め、印が付いている間は行動選択へ
  渡りません。PATCH で有効へ戻すときの扱いと揃えました。

## 指摘2［中］：終了中の根拠訂正を検知せず、完了日時付きで再有効化できる

**妥当。修正した。**

終了状態から `active` へ戻せないようにしました。指摘のとおり、PR1 で終了状態を
波及の対象外にした前提は「もう実行されない」ことでした。**再有効化を許すなら
その前提が崩れます。** 完了日時の扱いを定義するより、戻せなくするほうが
完了条件3（一度完了した質問を繰り返さない）を状態の上で保証できます。

前提が戻った場合は、新しい目標として作り直します（根拠も履歴も新しくなります）。
撤回（withdrawn）だけは戻せます。開発者が一時的に外すための状態で、戻すときに
根拠の有効性を確かめる既存の経路がそのまま使えます。

## 指摘3［中］：PATCH が採用の経路を迂回する

**妥当。修正した。** 依頼時に自分でも挙げた点で、塞ぐ側の判断をもらえたので
そのとおりにしました。

候補に対する `status` の変更を 409 で拒否し、`decide` へ誘導します。内容や
実行条件の修正は候補のままでもできます（採用前に直せないと、いったん採用して
から直すことになり、その間に実行されます）。

## 指摘4［中］：画面から撤回・再有効化・期限切れを行えない

**妥当。修正した。**

API が許す遷移と画面をそろえました。

- 採用済み：達成にする／撤回する／取り消す／期限切れにする
- **撤回中を独立した一覧にした**（戻せる状態なので、終わったものと混ぜない）。
  「戻す」「取り消す」を置いています。
- 終わったもの：操作を出さず、「ここからは状態を戻せません。前提が戻ったのなら
  新しい目標として作り直します」と明記しました。API の拒否と画面の説明を
  一致させています。

### 第2回レビュー（指摘4の残り）への対応

## 指摘4［中］：action の型が不正だと例外になる

## 指摘5［中］：待機の判断が記録に残らない

**妥当。修正した。** 依頼時に自分でも挙げた点で、置き場所の判断をもらえたので
そのとおりにしました。

`action_records` を新しく作りました（マイグレーション1版）。**発言を伴わない
判断も残します。** 会話・相手・行動・理由・候補の目標・選んだ目標・発言との
結び付き（待機なら NULL）・自発かどうかを持ちます。指摘のとおり、架空の空発言を
作って辻褄を合わせることはしていません。

`run_records` を広げなかったのは、`message_id` が必須かつ一意で、既存の
「発言から実行記録を引く」経路と一覧がそこに依存しているためです。

あわせて、自発発話で渡した可変状態のIDを記録していなかった点も直しました。

でした。渡ってはいけない記憶が渡っても落ちません。返答と同じ経路で読むように

## 指摘7［中］：open のモデル失敗が 503 にならない
