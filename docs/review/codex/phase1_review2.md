## 追加で確認した問題（重要度順）

### 1. [高] 移行前の未採用候補から、非公開記憶の越境が再発します

- 場所：[backend/alembic/versions/72df18ddda0e_add_visible_to_speaker_id.py](../../../backend/alembic/versions/72df18ddda0e_add_visible_to_speaker_id.py) 51行目
- 発生条件と影響：マイグレーションは `memories` の参照範囲を補完しますが、`memory_candidates` は列追加だけです。旧形式の未採用候補を用意して移行・採用すると、`visible_to_speaker_id=NULL` のまま保存され、**A由来の非公開経験がBの回答へ渡る**ことを再現しました。
- 修正方針：既存候補にも由来する会話から参照範囲を補完する。相手を特定できない場合の扱いも明示し、旧データ入りDBからの移行テストを追加する。

### 2. [中] 同じ会話の同時送信で、返答順序が逆転します

- 場所：[backend/app/agent/conversation.py](../../../backend/app/agent/conversation.py) 103行目
- 発生条件と影響：LLM待機前のコミットは適切ですが、同一会話の排他制御がありません。先の生成を待たせて次の質問を送ると、履歴が **「質問A → 質問B → 返答B → 返答A」** になることを再現しました。次回のプロンプトにもこの順序で入り、質問と返答の対応が崩れます。
- 修正方針：DBロックを解放したまま、会話単位で生成を直列化するか、処理中の追加送信を拒否する。終了操作との競合も同じ制御に含める。

### 3. [中] 振り返り中に処理が中断されると、再試行できません

- 場所：[backend/app/api/conversations.py](../../../backend/app/api/conversations.py) 101、112行目
- 発生条件と影響：生成前に `ended_at` を確定し、戻す処理は `LLMError` の場合だけです。生成待機中にタスクをキャンセルすると、**候補0件なのに再試行は409**になりました。プロセス停止でも終了状態だけが残り得ます。
- 修正方針：「振り返り処理中」と「完了」を区別し、中断・再起動後に未完了処理を回収できるようにする。

### 4. [中] 不正な根拠IDを、無関係な発言へ付け替えています

- 場所：[backend/app/agent/reflection.py](../../../backend/app/agent/reflection.py) 148行目
- 発生条件と影響：不正IDを最後のユーザー発言へ置き換えるため、前回の問題が条件付きで残っています。「写真が趣味」「今日はここまで」という同一会話で、不正IDを返すと、趣味の根拠が後者になることを再現しました。存在する発言でも、その内容の根拠とは限りません。
- 修正方針：不正IDは根拠未確認として扱い、再抽出・手動確認・候補除外のいずれかへ進める。無関係な発言を確かな根拠として保存しない。
