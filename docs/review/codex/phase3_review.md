## 指摘事項

### 1. [中] 人格の読込に失敗すると、振り返り開始済みの状態だけがDBに残ります

- 場所：`backend/app/api/conversations.py:151`、`:165`、`:174`、`:176`／`backend/app/main.py:24`／`backend/app/persona.py:25`
- 確認区分：コード確認のみ
- 発生条件：未終了の会話が存在し、既定人格がまだキャッシュされていないプロセスで、人格ファイルの欠落・TOML破損・定義不正がある状態から会話終了APIを呼ぶ。
- 影響：`reflection_started_at` をコミットした後に `load_persona()` が失敗します。`PersonaError` は例外処理の対象外なので、開始権を解除する `_release_reflection()` が実行されません。HTTP 500となり、人格ファイルを直しても、期限切れになるまでは再試行が409になります。既定値では180秒です。不変条件5の、振り返り失敗後に再試行できる既存動作を損ないます。また、人格の起動時検証は登録されていません。`PersonaError` の「起動時に落とす」という説明とは異なり、リクエスト処理まで障害を検出しません。
- 修正方針：振り返りの開始権を確定する前に必要な人格を解決する。読込失敗をAPIで適切なエラーへ変換し、開始後に失敗し得る場合は必ず開始権を解除する。既定人格を起動時に検証する方針なら、実際の起動処理へ組み込む。

### 2. [中] personas内のシンボリックリンクからディレクトリ外のファイルを読めます

- 場所：`backend/app/persona.py:90`、`:91`、`:97`、`:124`
- 確認区分：コード確認のみ
- 発生条件：`personas/test-b.toml` がディレクトリ外のファイルへのシンボリックリンクになっており、`test-b` を指定する。
- 影響：版名の文字列検証は通り、`available_versions()` にも列挙されます。`is_file()` と `read_text()` はリンク先を参照するため、外部ファイルが読み込まれます。内容が有効な人格TOMLなら人格として採用されます。不変条件4の「personasディレクトリの外を読めない」を満たしません。APIからリンクを作成できる経路は確認していません。これはローカルにリンクが存在する条件での不備であり、遠隔から任意ファイルを読めると断定するものではありません。
- 修正方針：人格ディレクトリと候補パスを解決し、解決後の候補がディレクトリ内にあることを検証する。一覧取得と読込で同じ制約を適用するか、人格ファイルのシンボリックリンクを禁止する。

## 対象外・未確認

- **キャッシュ：コード確認のみ。** キーに設定の版・ディレクトリが含まれず、`load_persona()`、`load_persona(None)`、明示的な版指定は別のキャッシュになり得ます。設定キャッシュだけを消しても人格・エージェントのキャッシュは残ります。ただし、稼働中の設定再読込を保証する仕様や本番経路は確認できないため、再起動まで反映されないこと自体は独立した不具合に数えていません。ファイル編集後の比較では再起動が必要です。

- **壊れた定義：コード確認のみ。** TOML破損、name欠落・空白、配列内の非文字列は拒否します。versionの省略はファイル名から補い、各配列の省略は空配列になります。追加の障害試験は未実施です。
- **テストの隔離：** 対象テストは `finally` で人格キャッシュを消し、プロパティ差し替えはmonkeypatchで復元します。依存差し替えもfixture終了時に解除します。今回の通常順序の実行では漏れを確認していません。任意順序・並列実行は未確認です。
- **移行：** 既存の移行テストはheadまで成功しました。新列の追加・削除はコード上対称ですが、既存run_recordsを含むupgrade／downgrade往復のデータ保持は未実行です。downgradeでは追加した版情報が失われます。
