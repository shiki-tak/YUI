### OnAir の扱い

設計書は「表示部分を参考・再利用する」としている。実際には**方式だけを参考にし、コードは取り込んでいない**。

- 参考にしたのは「口と目の開閉で4状態のPNGを切り替える」「リップシンクは実際に再生している音声から駆動する」という作り方。
- 取り込まなかった理由は、テンプレートが monorepo の一部で、表示だけを切り出しても周辺の依存が付いてくるため。設計書 §3 が避けている「OnAir を動かすためだけの構成」に近づく。
- 結果として `frontend/package.json` に新しい依存は増えていない。

## 構成

```
backend/app/
  voice/                音声合成モジュール（LLM接続と同じ形の窓口）
    base.py             SpeechClient / SpeechResult / SpeechError / WAVの長さ
    voicevox_client.py  VOICEVOX Engine への接続
  agent/delivery.py     再生状態の遷移規則
frontend/src/
  useSpeechPlayer.ts    再生器。1つだけ鳴らす、停止、音量の解析、待ち時間の計測
  components/AvatarPanel.tsx  アバター表示・口パク・まばたき・字幕・クレジット
frontend/public/avatar/ 口と目の開閉4状態のPNG
```

APIは21パス・25エンドポイント。テーブルは9つ（`speech_runs` を追加）。マイグレーションは4版。

## 採用技術

| 部分 | 採用 |
| --- | --- |
| 音声合成 | VOICEVOX Engine 0.25.2（macOS arm64・CPU版）＋ HTTPX |
| 話者 | 59（猫使ビィ／おちつき） |
| 再生 | ブラウザの `Audio` |
| 口パク | Web Audio の `AnalyserNode` による音量解析 |
| アバター | 口と目の開閉4状態のPNG（透過） |

VOICEVOX Engine は配布物をローカルに置き、リポジトリでは追跡しない。`dev.sh` は起動しないが、起動していれば版を表示して使い、無ければ警告して音声なしで続行する。

### クレジット表記

猫使ビィの音声を公開する場では「VOICEVOX:猫使ビィ」の表記が必要である。表記の文字列は設定（`YUI_VOICEVOX_CREDIT`）から画面へ渡し、アバターの下に常時表示している。話者を変えたときに表記だけ古いまま残らないようにするためで、設計書の配信・運用にも記録した。

## 設計上の約束と、実装での対応

| 設計の区別 | 実装 |
| --- | --- |
| 生成しただけの文章と、実際に話し終えた内容を混同しない | 読み上げる構成では返答を `generated` で作り、再生の通知で `playing` → `completed`／`aborted` と進める。開始・完了の時刻も残す |
| 音声が出せなくても会話は続けられる | 接続失敗・エラー応答・空の音声をすべて `SpeechError` にそろえ、API では 503 として返す。返答の文字は残り、`/api/health` の全体状態も下げない |
| 読み上げた内容と字幕を一致させる | 合成に渡すのも字幕に出すのも `messages.content`。別の文字列になる経路を作っていない |
| 合成エンジンを差し替えられるようにする | `SpeechClient` を窓口にし、VOICEVOX 固有の概念（話者ID、`/audio_query` の形式）を `voicevox_client.py` の内側に閉じた |

### 聞き直しと、実際に届いた1回目

再生状態には2つの規則を置いた。

- **すでに話し終えた（中断した）発言への通知は記録を動かさない。** 開発者が聞き直すたびに記録が上書きされると、実際に相手へ届いた1回目が分からなくなる。
- **鳴る前に止めた場合、開始時刻を入れない。** 鳴っていない音声を「再生した」ことにしないため。

## 素材（4状態のPNG）

生成された4状態のシートは、そのままでは使えなかった。セルごとに顔の大きさと髪飾りの形が違い、切り替えると髪とリボンごと画面が跳ねる。基準セルとの差は 2.3〜3.5% で、差は口や目だけでなく髪・服の輪郭全体に散っていた。

口閉じ・目開きのセルだけを土台にし、**口と目の領域だけを他のセルから移植**した。髪・服・リボンは常に同じ1枚から来るため、切り替えても動かない。

- 土台との差：口 0.13%、目 1.13%
- 4枚とも同じ切り取り位置・アルファチャンネルあり・緑の残り 0.000%

まばたきは、前髪が目に重なる部分だけ僅かに変化が残る。口パクには影響しない。目を描き直した素材ができれば、ファイルの入れ替えで差し替えられる。

## 待ち時間の計測

実機（M1 Max、qwen3.5:9b 思考出力なし、VOICEVOX 0.25.2 CPU版）で測った内訳。

| 区間 | 1回目 | 2回目 |
| --- | ---: | ---: |
| 記憶検索 | 1 ms | 0 ms |
| 返答の生成 | 1838 ms | 1009 ms |
| 音声合成 | 1807 ms | 1586 ms |
| 送信 → 再生開始 | 約 3.7 秒 | 約 3.4 秒 |
| 生成された音声の長さ | 9.9 秒 | 8.6 秒 |

- **記憶検索は無視できる**（1ms 未満）。[ISSUE-008](../issues/issues.md) の「全件をPythonで採点する」方式は、いまの記憶量では問題にならない。
- **待ち時間は生成と合成がほぼ半々**。片方だけ速くしても半分しか縮まない。
- 合成の時間は音声の長さのおよそ2割。返答が長いほど、生成も合成も遅くなる。
- 計測に使った返答はいずれも音声が9秒前後あった。人格の指示には「発言を短めにする」とあるが守られていない。

フェーズ2の完了条件に待ち時間の目標は無いため、ここでは測って記録するに留めた。改善案（返答を短くする／文単位で先に鳴らし始める／音声を保存する）は [ISSUE-012](../issues/issues.md) に効果と手間つきで記録した。

## 検証

- pytest **85件**（フェーズ1の41件に、ISSUE-003 で8件、フェーズ2で36件を追加）。一時DBを使い、通常利用の会話・記憶は変更しない。VOICEVOX を起動していなくても実行できる。
- フロントエンドのテスト **16件**（`npm test`）。再生の制御と会話の切り替えは画面側にあり、バックエンドのテストでは守れないため、レビュー後に Vitest を追加して固定した。
- ruff、TypeScriptの型チェック、Viteのビルド、`alembic check` によるモデル差分の確認がいずれも成功。
- 実エンジンに対する確認：`/audio_query` → `/synthesis` の順で正しいパラメータが渡ること、WAV と各区間の時間が返ること、`/api/health` がエンジンの版と話者を返すこと。
- ブラウザでの確認：自動再生、停止、聞き直し、アバターの口パクとまばたき、字幕。
- 実DBへのマイグレーション適用前にバックアップを取得した。

### 途中で見つけて直したもの

| 内容 | 原因 |
| --- | --- |
| API の日時が9時間ずれて表示される | 保存はUTCだが SQLite が timezone を落とす。読み出し側で補うようにした（`schemas.UtcDatetime`） |
| 新しい会話の1通目が自動再生されない | 会話IDが `null` から付くのを会話の切り替えと誤判定し、鳴らし始めた音声を自分で打ち消していた |
| 再生中に音声が止まる | 記録の通知で再描画されるたびに後片付けの副作用が走っていた。コールバックを ref に逃がして関数の同一性を保った |

Web Audio に音声をつなぐと、その経路からしか音が出なくなる。無音になる事故を避けるため、AudioContext が動いていなければ解析をあきらめ、先に音の経路を作ってから解析を枝分かれさせる順にしている。

### レビューで見つかり、直したもの

Codex による[レビュー](../review/codex/phase2_review.md)を2回受け、計6件の指摘をすべて修正した。いずれも非同期の順序に関わるもので、手で動かしても気づきにくい。

| 内容 | 影響 |
| --- | --- |
| 返答を待つ間に別の会話を開くと、遅れて届いた返答が現在の画面へ混入する | 表示している履歴と、次の送信先の会話が食い違う |
| 音声の取得中にアンマウントすると、後から再生が始まる | 操作できない音声が鳴り続けうる |
| 同時に届いた再生通知で、完了済みの状態が再生中へ戻る | 話し終えた記録が上書きされる |
| 再生開始後のエラーで、記録が再生中のまま残る | 鳴っていないのに再生中として残る |
| 履歴の読み込み中に送信すると、開こうとしている会話ではなく新しい会話へ入る | 選んだ会話と実際の保存先が違う |
| 通知の応答が入れ替わって届くと、話し終えた表示が再生中へ戻る | 画面の状態が実態と食い違う |

対応の詳細は [docs/review/claude/phase2_review_response.md](../review/claude/phase2_review_response.md) にある。この4件を機に、画面側のテストを追加した。修正を戻すと、追加したテストが実際に失敗することを確認している。
