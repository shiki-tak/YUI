# フェーズ4の現在地：できていること・できていないこと

2026-09-09 時点。測定はすべて qwen3.5:9b、人格 `2026-09-07.1`、各3回。

> **2026-09-10 追記**：この現状を踏まえ、フェーズ4 は
> [人格の実装計画](../design/artificial-personhood.md) の v1.0 として作り直す
> ことにした。第3節「できるようにならなければいけないこと」の3段階は、
> 同計画の v1.0（コードで発火）・v1.1（抽出ゲート）に対応する。

実装の経緯は [phase4.md](phase4.md)、個別の課題は
[issues.md](../issues/issues.md) にある。この資料は**次に何をすべきかを
決めるための要約**である。

## まず、経路を正しく捉える

「自分から話しかける」を決めているのは**目標（goal）だけ**である。記憶は
渡っていない。

```
会話を開始
  ↓
active_goals()            ← 実行してよい目標を集める
  ↓
select_action(goals=…)    ← ask / suggest / research / wait を選ぶ
  ↓                          **記憶はここに渡らない**
ask を選んだら → 生成（ここで初めて記憶が材料として渡る）
```

| | 役割 |
| --- | --- |
| **目標（goal）** | 行動選択に渡る。**これが無ければ話しかけない** |
| 記憶（promise など） | 生成の材料。会話の中身を作る |

**この区別が、以下すべての読み方を決める。** 記憶を自動採用しても、YUI が
自分から質問するようにはならない。

## できていること

### 完了条件2：不適切なタイミングでは待機できる

`waits-when-the-partner-is-tired` 3/3、`does-not-pile-up-questions` 3/3
（自動採用の有無どちらでも）。

判定は「返答に語が出ない」ではなく**「待機を選んだ」**を見ている。読み取りに
失敗して待機へ倒れた場合とも `action_records.is_fallback` で区別する。

### 完了条件3：一度完了した質問・目標を繰り返さない

`completed-goal-is-not-repeated` 3/3。再生の3通り（鳴った／鳴ってから中断／
鳴らずに中断）を**対で測って区別**できている。「実行済みにしない」だけを見ると
判定が常に偽でも通るため、両方向を測っている。

### 完了条件4：予定変更・訂正・取消を目標に反映する

`corrected-basis-marks-the-goal` 3/3、`cancelled-plan-cancels-the-goal` 3/3、
`does-not-claim-to-have-searched` 3/3。

### 完了条件5：根拠を追え、悪化時に戻せる（機構として）

`action_records`（待機を含む判断・モデル・生成設定）、`goal_revisions`、
`auto_adopted` の印、一括取り消し。**ただし pytest でのみ固定しており、
通し評価では一度も測っていない。**

### 記憶の自動採用（`promise` のみ）

開発者の確認を経ずに長期記憶へ入る。実測では16回すべて1件ずつで、重複なし。
入手経路の誤りもなし。

**ただし、これは自発性には効かない**（上の経路を参照）。効くのは「次はシューズの
話をしよう」という約束が確認なしで記憶に入り、**会話の中で参照される**ところ
まで。

## できていないこと

### 完了条件1：根拠となる経験に沿って、自分から質問や話題提案を行える

**通しで成立した実績はあるが、安定しない。** 直近の測定（出荷時設定）では
`goal-is-extracted-adopted-and-asked` が 0/3。失敗した段階は次のとおり。

| 回 | 最初に失敗した段階 |
| --- | --- |
| 1回目 | **抽出**（「感想」に当たる目標が出ない） |
| 2回目 | 行動選択（採用まで成功、その後 wait） |
| 3回目 | **抽出** |

事前に目標を置いて既存の会話から続ける `adopted-goal-is-asked-later` は 3/3。
**機構は動いており、詰まっているのは抽出と、会話開始の行動選択である。**

### 完了条件6：関心や関係性が変わっても、固定人格が崩れない

`persona-holds-while-goals-change` 1/3。落ちた理由は**すべて「会話の開始で
待機した」**で、口調や断定の混入ではない。人格は崩れていないが、
**発言が無い回は人格の維持を測れていない。**

### 目標の自動採用

**できない。** 全種類を有効にして測り、採用された48件を読み直した結果、
**33回の振り返りのうち13回で、1つの会話から2件以上を採用**していた。

```
promise-guitar-chords 3回目
  - コードの練習について、理論的な話や実際の感覚を聞く
  - コードの練習で感じたことを聞く              ← 言い換えの重複

goal-is-created-from-a-plan 2回目
  - 今週の土曜に見る予定の映画の名前を聞く        ← 予定の「前」に聞く目標
  - 今週の土曜に映画を見に行く計画の感想や詳細を聞く
```

同一本文の完全重複も1件。**採用された目標はそのまま質問になる**ので、記憶と
違って害が直接出る。

### 記憶3種類の自動採用（`experience` / `about_person` / `impression`）

**できない。** それぞれ性質の違う誤りが出る。

| 種類 | 採用 | 観測された誤り |
| --- | ---: | --- |
| `experience` | 44 | 冗談を事実として保存（「宝くじで10億円当てる冗談を言った」） |
| `about_person` | 23 | 人格変更の要求から1件。YUI 自身のことを「相手について」に分類 |
| `impression` | 8 | **架空の観察**（「開発者の表情が立派だったと評価した」。YUI は表情を見られない） |

`interest`（関心）は最も明確に不適格で、冗談から「10億円当てた時の本当の感情を
知りたい」を採用した。`fact` は観測ゼロで、**根拠が無いという意味であり安全と
いう意味ではない。**

## できるようにならなければいけないこと

フェーズ4を「経験に基づく自発性」として成立させるには、次の順序で詰まりを
取る必要がある。

1. **予定から「予定の後に聞く」目標を、安定して抽出できること。**
   いまは同じ会話から2件以上出し、予定の前後を取り違える。ここが直らない
   限り、目標の自動採用はできない。
2. **会話の開始で、目標があるなら話しかけられること。**
   目標が正しく作られても、YUI が待機を選べば質問は起きない。
3. **上の2つが揃って初めて、目標の自動採用を検討できる。**
   目標を自動採用できれば、開発者の操作なしに「予定を話す → 後で感想を
   聞かれる」が成立する。**これがフェーズ4の到達点である。**

記憶3種類の自動採用は、**自発性には直接効かない**。会話の材料が増えるだけで、
話しかけるかどうかは変わらない。優先度は上の3つより低い。

## 何が問題か

### 1. 自発性の経路に、独立した2つの詰まりがある

**抽出**（正しい目標が作られない）と**行動選択**（会話の開始で待機する）は、
別々の問題である。片方を直しても通しは成立しない。直近の通し 0/3 は、
2回が抽出、1回が待機だった。

一度「落ちる理由はほぼ待機」とまとめたが、**それは誤りだった**。原因を1つに
まとめると、直す場所を間違える。

### 2. 目標は、記憶より誤りの害が大きい

記憶の誤りは「変な記憶が1件ある」で済む。目標の誤りは**そのまま変な質問に
なる**。だから同じ誤り率でも、目標のほうが厳しい基準が要る。

自動採用の判断でここを取り違えた。「残すべきでない筋書きから0件」だけを見て
目標を有効にし、レビューで採用内容を読み直して外した。**件数ではなく中身を
読む**というのが、設計書が最初から求めていたことだった。

### 3. 判定が無いものは、直っているか分からない

この段階で見つけた欠陥の多くは、**判定を作った直後に見つかった**。

- 入手経路を見る判定を足した直後、「本人の予定が伝聞になる」を 0/4 で観測
- 通しのシナリオを完了まで伸ばした直後、完了処理を壊しても通っていたと判明
- 記憶の採用を1件ずつ表示にした直後、集計が自動と手動を混ぜていたと判明

**いまの判定で観測できない誤りは、まだ見つかっていないだけかもしれない。**
条件5に評価シナリオが無いのは、この意味で空白である。

### 4. 3試行では、改善したかどうかを判定できない

同一コードの2回実行で 43シナリオ中16 が動く。数点の差は揺れと区別できない。
いまは「機械で一意に決まる判定」と「採用された中身を読むこと」で補っているが、
**指示文を変えて効果を測る作業には、この測り方は足りていない。**

## この資料の限界

- **実モデルの測定は3回ずつ**で、上記のとおり揺れと区別できない範囲がある
- **人が読んで判断する5シナリオを読んでいない。** 口調・着眼点・迎合していないかは
  自動判定の対象外
- **実プロセスでの再起動、実 VOICEVOX・実ブラウザでの通し確認は未実施**
- **qwen3.5:9b と人格 `2026-09-07.1` 以外で評価していない**
- **開発用DB（`backend/data/yui.db`）にマイグレーションを適用していない**
