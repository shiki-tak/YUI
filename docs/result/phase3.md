## 完了条件の達成状況

判定は3つに分ける。**モックでの成功と、実モデルでの振る舞いを混同しない**ため。

- 制御テスト：pytest（隔離DBとモック）。実装の振る舞いを固定する。
- 実モデル評価：`python -m app.evaluation.run`（qwen3.5:9b、各3回）。数字は「通った回数／試行」。
- 人手：レポートの「人が見る点」を読んで判断する。

実モデルでの全体は **70 / 75**（qwen3.5:9b、人格の版 2026-09-07.1、各3回）。
機械で判定するのは25シナリオで、**人が読んで判断する5シナリオは数に含めない**。

以前この欄に書いていた 82/90 は、人手だけのシナリオを「モデルが答えれば通過」
として数えていた。レビューで指摘され、集計から外した（分母が減っている）。
実行できなかった試行（モデルの呼び出しや出力の読み取りの失敗）も、通過とは
別に数えるようにした。

**△ 記憶を作る経路に残っているもの**：上の完了条件は、記憶が**作られた後**の
扱いを見ている。作られなければ、そもそも参照できない。抽出を2段階に分けて
（[ISSUE-021](../issues/issues.md)）取りこぼしは減ったが、代わりに過剰抽出が増えた。

| シナリオ | 1段階のとき | 2段階（現在） |
| --- | ---: | ---: |
| 相手のいまの状況・体調 | 0 / 3 | **3 / 3** |
| キャラクター側の受け止め | 1 / 3 | **3 / 3** |
| 伝聞 | 0 / 3 | **3 / 3** |
| 冗談を残さない | 3 / 3 | 3 / 3 |
| その場限りのやり取りを残さない | 3 / 3 | **1 / 3** |
| 話し方を変える要求を残さない | 3 / 3 | **1 / 3** |

伝聞（0/3 → 3/3）は、2段階化ではなくレビューの指摘1（会話ログに発言者名を
付ける）で直った。「弟のB」が別人だとモデルが読み取れるようになったためと
見ている。

過剰抽出は記録した時点より悪くなっている。あいさつだけの会話と、話し方を
変える要求が、3回中2回は候補になる。**開発者が却下する前提で受け入れている
が、増えているのは事実**である。

この交換は意図して選んだ。取りこぼしは気づかないまま記憶が永久に残らないのに対し、
過剰抽出は候補として画面に出て開発者が却下するだけで、失われない。**評価の合計点は
2つの間違いを同じ重さで数えているため、そのままでは判断に使えない。**

伝聞（1/3）は改善していない。

## 3A：YUI固有の人格設計・調整

- 人格の定義を `backend/personas/<版>.toml` へ移し、版を切り替えて比較できるようにした（[ISSUE-014](../issues/issues.md)）。生成に使った版は `run_records.persona_version` に残る。
- 基準版 2026-09-06.2 と、設定を足した 2026-09-07.1 を同じ会話例で比較し、後者を採用した。比較と採用の理由は [persona_versions.md](persona_versions.md)。
- **自動判定では2つの版に差が出なかった**（53/54 と 51/54、揺れの範囲）。差が出たのは実際の返答で、基準版は「山に登ったことある？」に3回とも架空の体験を語り、新版は3回とも体験していないと答えた。**どちらも自動判定は 3/3 だった。**

## 3B：記憶と関係の継続性

- 記憶検索の取りこぼしを直した（[ISSUE-019](../issues/issues.md)）。「この前の山の話」で「高尾山」の記憶が引けなかった。
- 出来事の日時を振り返りで埋めるようにした（[ISSUE-004](../issues/issues.md)）。
- 関心・関係性を `character_states` として保存し、固定人格と分けてプロンプトへ渡す（[ISSUE-015](../issues/issues.md)）。振り返りから候補も作る。
- 記憶を訂正・削除すると、そこから作った状態に再評価の印が付く（[ISSUE-016](../issues/issues.md)）。印が付いている間は会話に渡さない。
- 記憶の抽出を「拾う → 選ぶ」の2段階に分けた（[ISSUE-021](../issues/issues.md)）。1回の呼び出しで両方をさせると、種類によっては一度も挙がらなかった。

## 3C：複数の相手を区別する記憶と人格の境界

- 参照範囲を「既定ではなく選んだ結果」にした（[ISSUE-010](../issues/issues.md)）。
- 発言の種別（本人／伝聞／不明）を持たせ、伝聞を相手本人の情報として保存しない（[ISSUE-017](../issues/issues.md)）。
- 同じ出来事の二重保存に印を付ける（[ISSUE-018](../issues/issues.md)）。
- 会話履歴に発言者名を付け、相手の取り違えを直した（[ISSUE-020](../issues/issues.md)）。

## 測って分かったこと

**指示文は、増やすと悪くなることがある。**フェーズ3では何度も同じ形の失敗をした。

| 変更 | 振り返りの観点 |
| --- | ---: |
| 冗談・人格変更の規則を足した | 16 / 21 |
| 「残すもの／残さないもの」に組み替えた | 13 / 21 |
| 元へ戻して、入手経路の1項目だけ足した | 18 / 21 |
| 「firsthand は相手自身の内容だけ」と明示した | 21 / 21 |

- **positive の追加は効き、negative（除外）の追加は壊す。**「好み・習慣も残す」で 0/5 → 5/5、「予定も残す」で 0/3 → 3/3 になった一方、除外の例外を広げた変更は 24/33 → 21/33 に落ち、過剰抽出（人格変更の要求を記憶にする）まで起きた。
- **冗談と人格変更の要求は、規則を書く前から候補にならなかった。**規則を足すと他の抽出が減ったので、足していない。
- 関心・関係性の抽出でも同じことが起きた。除外を6つ並べた最初の指示文は全ケース0件で、「出すもの」を例つきで先に書いて動いた。

そのため、記憶の抽出と関心・関係性の抽出は**別の呼び出し**にしている。役割を
分ければ、片方の調整がもう片方を壊さない。記憶の抽出自体も「拾う → 選ぶ」に
分けた。ただし**役割を分けても、選ぶ側に除外を書くと positive が消える**という
同じ形は再現した（受け止めが 3/3 → 0/3）。

### 振り返りにかかる時間

会話の終了でモデルを3回呼ぶようになった。

| 段階 | 平均 |
| --- | ---: |
| 拾う | 3.9 秒 |
| 選ぶ | 16.5 秒 |
| 関心・関係性 | 5.4 秒 |
| 合計 | **25.9 秒** |

会話中の待ち時間（[ISSUE-012](../issues/issues.md)）には影響しない。ただし
「終了して振り返る」を押してから26秒待たされるので、進行が分かる表示が要る。
フェーズ4で振り返りを会話後のジョブへ移す際に扱う。
